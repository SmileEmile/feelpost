## 3. P0 阻塞项

### B1 契约与持久化字段缺失

当前代码没有以下字段：

- `Preferences.ai` / `AIConfig`；
- `ProjectDetail.aiHandoffDocumentId`；
- `RequestDraft.fieldDescriptionMeta`；
- `ResponseExample.fieldDescriptionMeta`；
- `Case.aiMeta`；
- `ErrorCode` 中的 `AI_*`；
- `FeelpostApi.ai`、`FeelpostApi.aiDoc`。

**影响**：无法通过类型检查；preload 无法暴露 AI；AI 结果写入后无法追溯。

**处理**：先做契约变更和迁移，再写 AI 服务。旧数据按可选字段处理，不提升 `schemaVersion`；AI 文档目录惰性创建。

### B2 AI 文档读取 API 缺失

设计已补 `aiDoc:get`，但实现层需要明确：

- `aiDoc:list` 只返回摘要；
- 打开 AI 文档页面必须调用 `aiDoc:get` 拿完整版本；
- `AIDocumentSummary` 不能包含全部 Markdown，避免列表载荷过大；
- `aiDoc:save` 返回完整文档，前端可直接更新当前视图。

**状态**：设计已补；实现时作为必做通道，不可用 `list` 替代。

### B3 AI 用例缺少环境与应用上下文（设计已关闭）

现有 `CaseService.create` 强制要求 `envId`。已确认：

- AI 生成阶段不绑定环境；
- 导入时使用当前工作区环境，预览中明确显示环境名；
- `ai:importCases` 增加 `envId`；
- 服务端复用 `CaseService.create`，并补 `aiMeta` 与 `#AI`；
- 生成上下文自动参考当前接口最近 3 个用例。

**实施注意**：环境在用户点击导入时可能被切换，主进程必须重新校验 `envId` 属于当前项目。

### B4 safeStorage 不可用时的降级（设计已关闭）

`Preferences` 是普通 JSON；`safeStorage` 在无桌面密钥环环境可能不可用。已确认：

- 不可用时**不写明文**；
- Key 只保留在当前会话内，`keyStorageMode='session'`；
- 应用退出即失效，设置页明确提示；
- 系统安全存储可用时使用 `persistent`。

### B5 项目文档 AI 章节的范围语义（设计已关闭）

`DocService.buildProject` 支持 `scope` 与多种 filter。已确认：

- 首版只在**未启用筛选且 `scope='active'`** 时追加 AI 章节；
- 有筛选时保持基础文档，避免出现范围外内容；
- 独立 AI 文档仍可单独查看/导出。

## 4. P1 实现风险

| 编号 | 风险 | 缓解 |
|---|---|---|
| R1 | 上下文包含环境 Header / Cookie / URL token | Redactor 覆盖 header、cookie、query；发送前展示脱敏预览 |
| R2 | SSE 流式失败后重试产生重复文本 | 每次重试使用新 buffer；只有 completed 结果可应用 |
| R3 | 模型返回 JSON 不合法 | zod + 字段路径校验；仅对格式/网络错误重试一次 |
| R4 | 流式输出取消后仍写入 | requestId + AbortController；取消后丢弃 buffer |
| R5 | AI 文档版本无限增长 | 服务层裁剪到 10 版；原子写 |
| R6 | API Key 出现在日志 | 独立 secret store；日志只记录 provider/model/host |
| R7 | AI 字段说明覆盖人工内容 | 只补空字段；已有说明 Diff；人工修改清除该字段 AI meta |
| R8 | 多接口选择无现有 UI | DocsView 增加选择模式；最多 20 个接口 |
| R9 | 现有 `doc:build` 输出被 AI 章节污染 | AI 章节由独立 `AIDocumentService` 提供；基础 6 块不变 |
| R10 | 测试依赖真实模型 | ProviderClient 注入 mock；默认测试不发网络请求 |

## 6. 建议实施顺序

### Phase 0：契约与迁移

- 更新 `contract.ts`、错误码、preload 类型；
- 增加路径与 legacy 默认值；
- 为旧数据补默认/可选字段；
- 不接 UI，先通过类型检查。

### Phase 1：AI 基础设施

- 设置页 AI 配置；
- safeStorage 封装，测试注入 fake secret store；
- ContextBuilder + Redactor + hash；
- ProviderClient（mock + SSE + abort + timeout）；
- `ai:previewContext` / `ai:generate` / `ai:cancel` / 事件。

### Phase 2：字段说明

- `ai:applyFieldDescriptions`；
- 请求体与响应字段 Diff；
- AI meta 与人工修改清理；
- 单接口验收。

### Phase 3：AI 用例

- 生成、场景、候选抽屉；
- 当前环境导入；
- #AI + aiMeta；
- 不自动发送。

### Phase 4：AI 接入文档

- 多接口选择；
- `aiDoc:get/save/list/insert/remove`；
- 项目文档固定章节；
- 最近 10 版。

### Phase 5：安全与验收

- 上下文/Key 泄漏测试；
- 失败、超时、取消、重试；
- 打包冒烟；
- 设计文档与 README 同步。

## 7. 测试与验收门槛

### 必须通过

1. `npm run typecheck`
2. `npm test`（至少新增 5 组 AI 单测）
3. `npm run build`
4. AI 配置保存后，渲染进程无法读取 Key
5. 上下文预览中 Authorization/Cookie/token 已脱敏
6. 字段说明只补空，已有说明 Diff 不默认覆盖
7. AI 用例导入带 `#AI` 与 `aiMeta`，环境快照正确
8. AI 文档保存/读取/10 版裁剪/项目指针
9. 取消或失败不产生半写入
10. 未配置 AI 时核心功能不回归
