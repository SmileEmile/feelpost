## 1. 项目背景与定位

### 1.1 要解决的问题

AI 辅助开发已经是"后端 AI 写接口、前端 AI 写页面"的协作形态，但两者之间缺一条**接口契约的搬运通道**：

1. 后端 AI 写完接口后，开发者需要**人工验证**接口是否符合预期——目前只能手工往 Postman / Apifox 里录入；
2. 接口文档靠手写或额外工具生成，与代码不同步，前端 AI 拿到的常是过期契约；
3. 政企、通信、银行等内网环境有严格网络管控，联网型工具的校验与加载会直接卡死工作流。

### 1.2 产品定位

feelpost 是**面向 AI 协作开发流程的本地接口契约中枢**：从 Java 源码自动产出可信的接口契约，在本机完成调试与验证，再把结构化的接口文档交给 AI 前端消费。

**定位边界（已确认）**：本产品的差异化不在"调试"（该能力已被 Postman 覆盖），而在"从源码自动产出可信契约 + 面向 AI 的文档产物"。调试器是必要条件，不是竞争点。

### 1.3 软件形态

- 桌面客户端，名称 **feelpost**
- 本地运行，**离线可用为硬底线**：不依赖在线资源、不依赖联网校验
- **单机、单用户**：无账号体系、无服务端、无多人协作
- 数据全部存放在本机目录
- 支持 **Windows 与 macOS**

## 2. 目标用户与核心场景

| 角色 | 核心诉求 | 典型场景 |
|---|---|---|
| 全栈开发者（AI 辅助开发主力） | 一个人跑完"后端 → 验证 → 文档 → 前端"闭环，不手工抄接口 | AI 生成 Controller 并重启服务后，一键增量扫描，验证接口是否符合预期，保存响应示例，导出 md 交给前端 AI |
| 后端开发者 | 自测与回归快、多环境切换顺、token/cookie 不反复填 | 在本地/测试/生产三套环境间切换，验证鉴权与参数组合 |
| 前端开发者 | 拿到可直接喂给 AI 的契约与响应样例 | 后端接口刚变更，需要最新字段定义与真实响应结构 |
| 内网/涉密环境开发者（政企、通信、银行） | 断网可用、数据不出本机、启动即用 | 网络强管控下，联网型接口工具无法使用或不稳定 |

**核心业务目标**：让"AI 写的后端"与"AI 写的前端"之间的接口契约零手工搬运。

**建议的验收指标（待确认，未定稿）**：
- 一个已在运行的 Spring Boot 项目，从"开始扫描"到"导出 md"≤ 3 个界面操作步骤；
- 常规注解式 Controller 的接口发现率 ≥ 95%（口径与样本待定义）；
- 断网状态下完成完整主流程，不出现任何联网等待。

## 4. 核心业务流程

### 4.1 主流程

1. **选择项目目录**：用户指定本机的 Spring Boot 工程根目录；
2. **扫描**：手动触发，全量或增量；解析注解、路径、参数、DTO、Javadoc 与校验注解；
3. **授权入库**：扫描结果进入待确认队列，按"新增 N / 变更 M / 删除 K"分类批量勾选；
4. **选择环境**：环境 = 前置 URL + 一整套参数与凭据；切换环境后整套生效；
5. **确认生效参数**：界面展示全局参数与环境参数合并后的最终请求参数；
6. **直接调用**：发送请求，查看状态码、响应体、耗时；
7. **保存产物**：保存响应示例；将当前请求保存为用例（冻结快照）；
8. **汇总与导出**：用例汇总页查看项目全部用例；导出 md 给 AI 前端使用。

### 4.2 分支与异常流程

| 场景 | 期望行为 |
|---|---|
| 接口解析失败 | 接口仍可入库，标记"部分解析/失败"，允许人工补全字段 |
| 手工新建接口 | 标记来源为"手工"，不参与扫描对比 |
| 扫描发现接口变更 | 状态变为"已变更"，提示受影响的用例"基于旧定义"，不自动改写用例 |
| 扫描发现接口删除 | 状态变为"已归档"，保留历史文档与用例 |
| 请求失败（证书/代理/超时） | 明确区分"证书校验失败""代理不可达""服务未启动"，并给出对应开关位置 |

## 5. 功能需求

### 5.1 扫描与索引（FR-S）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-S1 | 支持选择本地 Spring Boot 工程目录（Maven/Gradle）作为扫描根 | 能处理多模块工程；可排除目录（如 `target/`、生成代码） |
| FR-S2 | 识别 REST 接口：GET / POST / PUT / DELETE | 覆盖注解式 Controller（类级 + 方法级路径拼接、context-path） |
| FR-S3 | 解析参数：Path / Query / Header / Body(JSON、form、multipart) / Cookie | 输出字段名、类型、嵌套结构、是否必填、默认值 |
| FR-S4 | 从 Javadoc 与校验注解提取说明与约束 | `@NotNull`/`@Size` 等转为必填与限制说明；取不到时降级 |
| FR-S5 | 每个接口标记解析完整度：完整 / 部分 / 失败 | 失败原因可查看，允许人工修正 |
| FR-S6 | 全量扫描与增量扫描 | 增量基于上次扫描快照 + 接口指纹（方法 + 完整路径），不依赖文件时间戳 |
| FR-S7 | 识别新增 / 变更 / 删除 | 变更需能指出差异范围（至少到"参数有变化"级别） |
| FR-S8 | 扫描过程可中断、显示进度 | 1000 接口量级下扫描不阻塞界面；可随时取消 |

### 5.2 接口注册与生命周期（FR-R）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-R1 | 扫描结果进入待确认队列，需用户授权后入库 | 按新增/变更/删除分类，支持勾选与批量通过 |
| FR-R2 | 接口状态机：待确认 → 已注册 → 已变更 → 已归档 | 状态可筛选；"已变更"需可追溯到上次扫描 |
| FR-R3 | 人工层数据不被扫描覆盖 | 用户补充的说明、响应示例、标签在重新扫描后保留 |
| FR-R4 | 支持手工新建接口 | 标记来源为手工；不参与扫描对比，可手动归档 |
| FR-R5 | 接口按项目组织，可按方法/路径/名称筛选检索 | 1000 接口下检索响应可接受 |

### 5.3 环境与全局参数（FR-E）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-E1 | 环境 = 前置 URL + 一整套 header/query/body/cookie/凭据 | 新建/编辑/克隆/删除环境；切换后整套生效 |
| FR-E2 | 全局参数作为公共值，环境覆盖全局 | 调试页展示"合并后的最终生效参数"，可展开查看来源 |
| FR-E3 | token / cookie 手工填写 | 无自动登录、无跨请求变量引用 |
| FR-E4 | 证书校验开关与代理设置（含免代理名单） | 默认跟随环境；内网自签证书场景可一键跳过校验 |
| FR-E5 | 环境可筛选接口维度展示 | 切换环境不改变接口清单，只改变请求上下文 |

### 5.4 调试执行（FR-D）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-D1 | 请求构造覆盖 path / query / header / body / cookie | 参数类型与必填提示来自扫描结果 |
| FR-D2 | 请求体支持 JSON、form-urlencoded、multipart 文件上传 | 文件上传需可选择本地文件并预览已选文件 |
| FR-D3 | 发送请求并展示状态码 / 响应头 / 响应体 / 耗时 / 响应大小 | 大响应可折叠/格式化查看 |
| FR-D4 | 保存响应示例到接口 | 支持多份示例，标注来源用例与时间 |
| FR-D5 | 复制请求为 curl 命令 | 包含当前环境的前置 URL 与生效参数 |
| FR-D6 | 请求失败给出可操作提示 | 证书、代理、超时、连接拒绝分别提示 |

### 5.5 用例（FR-C）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-C1 | 将当前请求保存为用例，保存的是**冻结的完整请求快照** | 一个接口可保存多组用例（正常/异常/边界） |
| FR-C2 | 用例归属接口与项目；可打标签/备注 | 标签可筛选、可用于待确认清单 |
| FR-C3 | 用例汇总页展示项目内全部用例 | 支持按接口、标签、时间筛选 |
| FR-C4 | 接口变更后提示受影响用例 | 仅提示"基于旧定义"，不自动修改用例内容 |
| FR-C5 | 用例不定义期望结果 | 无断言、无自动回归——执行仍是手工触发 |

### 5.6 文档与导出（FR-T）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-T1 | 接口文档以本地 JSON 存储，按项目组织 | 数据目录可直接查看与备份 |
| FR-T2 | 导出项目级 md，固定 6 块：接口清单 / 方法+URL / 参数表（名·类型·必填·说明）/ 请求示例 / 响应示例 / 字段说明 | 不含用例、不含"鉴权要求"字段 |
| FR-T3 | 导出内容取自"源码层 + 人工层"合并结果 | 人工补充的说明与示例要出现在导出中 |
| FR-T4 | 复制接口信息为 curl | 与 FR-D5 一致 |
| FR-T5 | 可用例汇总视图导出给 AI 前端参考 |

### 5.7 界面与主题（FR-U）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-U1 | 信息架构参考 Postman / Apifox：项目 → 接口列表 → 调试/文档/用例 | 三栏或等效布局；键盘操作不阻塞 |
| FR-U2 | 浅色 / 深色主题切换 | 切换后全界面一致；主题选择本地持久化 |
| FR-U3 | 扫描结果、变更确认、用例汇总为高频页面 | 交互路径短，无多余弹窗 |

## 6. 核心概念（概念级，不含表结构）

| 概念 | 定义 |
|---|---|
| 项目 | 数据组织的第一维度，对应一个本地工程目录；接口、环境、用例均归属项目 |
| 接口 | 一个有身份的 API 端点（方法 + 完整路径），包含源码层与人工层 |
| 源码层 | 由扫描获得：路径、方法、参数与类型、Javadoc、校验注解、解析完整度 |
| 人工层 | 由用户维护：补充说明、响应示例、标签；扫描永不覆盖 |
| 环境 | 前置 URL + 一套参数与凭据的集合；可切换、可筛选 |
| 全局参数 | 跨环境共享的公共参数，被环境覆盖 |
| 用例 | 冻结的请求快照 + 归属接口 + 标签/备注 |
| 扫描快照 | 上次扫描的接口指纹集合，用于增量与变更判定 |

**说明**：本文档不定义存储结构。是否保留"调用历史"、数据目录的具体布局、项目与环境的物理边界，均留待总体设计阶段确认。

## 7. 业务规则

1. **接口身份**：`HTTP 方法 + 完整路径` 是唯一身份；同路径不同方法视为不同接口。
2. **接口指纹**：由方法、完整路径、参数集合摘要构成，用于增量对比；参数变化即视为"已变更"。
3. **分层合并**：源码层随扫描更新；人工层只追加、不覆盖；导出与展示取两者合并。
4. **授权入库**：任何扫描产出在入库前必须经用户确认，不静默写入正式清单。
5. **参数优先级**：环境参数覆盖全局参数；同一位置（如 header）同名键由环境值胜出。
6. **用例快照**：用例保存后与接口定义解耦；接口变更只产生提示，不改写用例。
7. **环境隔离**：切换环境只影响请求上下文，不影响接口清单与用例内容。
8. **失败降级**：解析失败不阻塞入库，转为"部分解析/失败"状态等待人工补全。

## 8. 非功能需求

| 类别 | 要求 |

## 9. 已接受的取舍与风险

| 编号 | 取舍/风险 | 影响与缓解 |
|---|---|---|
| R1 | 扫描仅支持 Spring Boot 注解式代码 | 解析准确率强依赖代码规范（DTO 清晰、注解完整）；缓解：解析完整度标记 + 人工补全 |
| R2 | 凭据明文落盘 | 政企/银行内控审计可能不通过；缓解：把凭据集中在一个配置块，未来可整体加密迁移，不影响其他数据 |
| R3 | 双平台（Windows + macOS） | 打包与 UI 回归成本翻倍；缓解：为两平台分别定义 MVP 验收清单 |
| R4 | 文档不含"鉴权要求" | 前端 AI 可能把需登录接口当公开接口；缓解：该决定可逆，日后在 md 补一行即可 |
| R5 | v1 无断言/无回归 | 用例只能人工复跑；缓解：v2 评估接入断言 |
| R6 | 无导入 Postman/Apifox | 存量用户迁移成本高；缓解：md/curl 可作为迁移桥梁 |

## 14. v1.1 增补确认（2026-11-19）

> 本节为需求冻结后的增补，不推翻原 Q1–Q23 与 FR 条目；设计阶段的逐条结论见 `docs/design/01.功能模块梳理.md` §9.0。

### 14.1 原型评审新增需求

| 编号 | 内容 | 说明 |
|---|---|---|
| A-1 | 新建项目支持系统目录选择器 | 选择后回填工程根目录，并识别构建文件（`pom.xml` / `build.gradle`）与 Controller 数量；仍允许手填路径 |
| A-2 | 扫描范围支持"整个工程 / 指定目录 / 指定模块" | "模块"= Maven 模块 → 包 两级；支持模块整选与半选；局部扫描的比对范围见 DQ1 |
| A-3 | 接口树按 Maven 模块 → 包两级组织 | 默认收起为模块列表，可展开全部 / 收起全部；折叠状态在筛选时保留 |

### 14.2 设计阶段确认（DQ1–DQ19）

| 编号 | 结论 |
|---|---|
| DQ1 | 扫描快照为项目级；局部扫描只更新所选范围，范围外标记"未比对" |
| DQ2 | 解析不完整接口的人工修正存人工层，展示时覆盖源码层，扫描不改写；指纹只取源码层 |
| DQ3 | "已变更"由用户"确认变更"后回到"已注册" |
| DQ4 | 手工接口单列"手工接口"根级分组，不归属 Maven 模块，不参与扫描比对 |
| DQ5 | 用例允许重命名、复制、改标签/备注；请求快照不可编辑 |
| DQ6 | 证书校验与代理按环境配置，全局提供默认值；支持免代理名单 |
| DQ7 | 单接口文档预览/导出纳入产品需求 |
| DQ8 | 扫描结果页取消授权即丢弃本次结果，不保留草稿 |
| DQ9 | 接口树始终为项目全量，另提供"只看本次扫描"临时筛选 |
| DQ10 | 已归档接口可恢复为已注册；不做物理删除；导出默认排除归档接口 |
| DQ11 | 项目支持重命名与删除（删除需二次确认）；更换源码目录后重新扫描 |
| DQ12 | 支持 PATCH，HEAD 后置 |
| DQ13 | 不自动重试；超时默认 30s，按环境可配置 |
| DQ14 | 环境/全局 Body 仅补缺，不覆盖接口已有值 |
| DQ15 | 主题只做明暗两套 |
| DQ16 | 支持数据目录整目录拷贝/备份 |
| DQ17 | 扫描默认排除 target/build/node_modules/.git 等，可自定义追加 |
| DQ18 | 导出设置提供"包含手工接口"开关，默认包含；不做单列与额外来源标注 |
| DQ19 | 更换源码目录后，旧接口保留并标记"目录已变更"，待下次扫描比对，不自动归档或删除 |
